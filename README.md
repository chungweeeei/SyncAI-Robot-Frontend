# SyncAI-Robot-Frontend

The operator console for one SyncAI robot: watch telemetry, drive it, and
manage its maps, recordings and jobs. It is a browser client of
`syncai_backend` and nothing else — every REST call and WebSocket stream goes
to that process on port **3000**.

Next.js 16 (App Router) + React 19, shadcn/ui on `@base-ui/react`, Tailwind 4,
TanStack Query with zod-validated reads, raw three.js for the 3D views, and
WebRTC for the camera. `CLAUDE.md` holds the rules for working in the code.

## Running

```bash
npm ci             # the lockfile is authoritative; Node >= 22
npm run dev        # http://<host>:3001, HMR
npm run build && npm start

npm run lint       # eslint, including the layering rule
npx tsc --noEmit   # type check alone
npm test           # unit tests (vitest)
npm run test:e2e   # end-to-end (playwright; builds and starts the app itself)
```

CI (`.github/workflows/ci.yml`) runs the same gates on every push and PR to
`main` and `dev`. The e2e suite fakes the backend per test (`e2e/backend.ts`),
so it needs no robot.

## Ports and backend addressing

The console listens on **3001** in dev, `npm start` and the container, so it
can share a host with the backend without a proxy. Every backend path goes
through `apiUrl()` / `wsUrl()` in `lib/api/config.ts`, resolved in this order:

1. `NEXT_PUBLIC_API_BASE` / `NEXT_PUBLIC_WS_BASE`, if set at build time;
2. the page's own hostname on port 3000 (what makes `http://<robot-ip>:3001`
   work on the LAN);
3. `http://localhost:3000` for SSR and the build.

**Reaching the dev server by name.** Next 16 trusts only `localhost` for
dev/HMR; `next.config.ts` adds this host's own addresses at startup. For a
hostname (mDNS, DNS, a proxy, a tunnel), list it — no scheme or port:

```bash
SYNCAI_DEV_ORIGINS=robot-01.lan,10.8.140.138 npm run dev
```

## Routes

| Route | What it is |
|---|---|
| `/` | Dashboard: the 3D view (live scan, the map's scan and 3D map, robot, route, waypoints, forbidden zones) and the instrument rail (schedules, locomotion, motors). |
| `/mapping` | Build a map: switch to Mapping, **Start mapping**, drive, then **Save** (or **New map**). |
| `/maps` | Map library: switch, rename, delete, export / import, and open a map's editor. |
| `/maps/[name]/edit` | The map's editor. Floor plan view: cells, waypoints and forbidden zones. `?view=3d`: the 3D map's ground patches (Fill / Erase), waypoints and forbidden zones. Changes are staged and sent by **Save**. |
| `/recordings` | Start, watch and manage recordings on the robot. |
| `/tasks`, `/tasks/editor` | Saved jobs and schedules; the step editor. |
| `/history` | Finished runs, with counts and success rate. |
| `/settings` | Planner, Controller, Wi-Fi, Preferences, and **Restart**. |
| `/drive` | Full-screen drive sticks for a phone (unlisted). |
| `/webrtc-test` | The WHIP/WHEP bench (unlisted, but in every build). |

A map a job is driving on is read-only until the job ends; the backend
refuses the write and the console greys the control first.

The masthead on every route carries the robot id, the **emergency stop**
(one press engages, a one-second hold releases), sensor alerts, the drive
panel, the camera window and the running job's controls.

## The robot mesh

`public/models/g23.glb` is generated by `scripts/urdf2glb.py` in the
`SyncAI-Robot-Workspace` repo. Re-bake after any URDF change, keeping two
invariants the dashboard depends on:

- GLB node names **equal URDF link names** (`lib/robot/g23-joints.ts` maps
  joint angles to meshes by them).
- Coordinates stay **Z-up**, as in ROS, not glTF's +Y-up.

## Container image

`cp .env.example .env`, then build and run:

```bash
docker compose build frontend-build
docker compose up -d frontend      # http://<host>:3001
```

Or pull the published image (arm64 + amd64) by setting it in `.env`:

```bash
FRONTEND_IMAGE=ghcr.io/chungweeeei/syncai-robot-frontend
FRONTEND_TAG=1.2.0          # or `main` to track the release branch
```

```bash
docker compose pull frontend && docker compose up -d frontend
```

`NEXT_PUBLIC_*` are **build args**, not runtime environment — Next inlines
them — so pointing at a backend on another host means setting them and
rebuilding. Leave them empty for the same-host case. Every push to `main`
moves the `main` tag; a `vX.Y.Z` tag on `main` publishes `X.Y.Z`, `X.Y` and
`latest` (`.github/workflows/release.yml`). GHCR creates the package
private: make it public on GitHub, or every robot has to `docker login`.

On the robot today, this repo sits inside the `SyncAI-Robot-Workspace` tree
and `NodeManager` runs `npm run dev`.
